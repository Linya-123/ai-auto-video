# AI 自动化剪辑 Skill｜一句话，从选题到成片

**把选题交给 AI，让它串起文案、配音、画面、动效、字幕和导出。**

面向个人 IP、知识科普和教程讲解的视频制作工作流。你确定方向和生成方案，Agent 负责调用工具、组织素材、制作镜头与检查成片；已有角色、文案或音频，也能从中途接着做。

**适用于 Codex、WorkBuddy 等具备文件读写、脚本执行和工具调用能力的 AI Agent。** 不绑定单一大模型；生成与渲染能力通过当前环境的工具、本地模型或 API 接入。

## 你给一个选题，Agent 接手这些工作

| 阶段 | 完成什么 |
|---|---|
| 准备 | 检查可用工具，选择生成方案，建立独立项目与共享素材库 |
| 建立 IP | 角色、三视图、场景与笔触参考，让镜头有一致的视觉依据 |
| 写稿配音 | 原创口播、现成音色或自己的声音，也可保留已有配音 |
| 安排镜头 | 按实际语音时间设计分镜，让画面解释内容 |
| 动效剪辑 | 制作人物画面、知识图解、字幕和混音，导出MP4 |
| 检查交付 | 检查声画与工程，保留可修改版本，确认后清理旧产物 |

**可以做完，也可以接着改。** 换一个镜头不必重配整片声音；已有满意素材优先复用，中断后从项目状态继续。

## 三步开始制作

### 1. 让 Agent 读取 Skill

下载本仓库，将 `ip-video-pipeline/` 放到所用 Agent 支持的技能目录。Codex 可使用 `~/.codex/skills/`，刷新技能列表或开启新会话后调用 `$ip-video-pipeline`。

WorkBuddy 或其他 Agent 按各自的技能导入方式安装；如果没有技能入口，可把整个文件夹交给 Agent，并要求它先读取 `SKILL.md`、再按需读取引用文档。不同产品的安装位置与可用工具可能不同，不需要照搬 Codex 的路径。

### 2. 复制这段需求，换成你的选题

```text
使用 ip-video-pipeline，帮我做一条约60秒的知识视频。
主题：[你的选题]；受众：[给谁看]；画幅：[横屏或竖屏]。
在源码仓库外新建制作工作区；有现成角色就复用，没有就设计原创IP。
先说明当前可用的生图、配音方案和优劣，我选定后自动完成制作，
包括文案、整段配音、对齐、分镜、画面、动效、字幕与导出。
过程中自己检查并修复，最后交付成片和可重渲染工程，
让我确认最终采用版本和旧文件清理清单。
```

### 3. 选好工具，等待成片

Agent先检查环境，仅准备所选路线缺少的依赖。首次配置完成后，后续视频优先复用。无需前置试听，也无需手动逐个运行脚本；缺少必要账号或素材时，会指出具体缺项。

- **复刻自己的声音**：提供自己的参考音频或本地路径。
- **使用付费API**：申请对应服务的API Key并准备额度，在本地配置密钥，不发送到聊天或仓库。
- **已有文案、角色、配音**：提供所在目录，说明需要保留的版本。

继续修改时直接说：

```text
继续这个项目：[项目目录]。
保留已确认的角色和配音，只修改我指出的镜头，然后重新导出。
```

## 哪些 Agent 能用？

这是一套可移植的 Skill 文档与Python脚本，面向 Codex、WorkBuddy 等能执行任务的 Agent。完整制作需要：读取项目文件、执行本地命令，以及访问所选图像、音频和渲染工具。仅能聊天、无法调用这些工具的环境不能独立跑完整流程。

现有案例在 Codex 环境完成；这里没有声称每款 Agent 都做过完整适配测试。其他环境按实际权限与工具接入。图片生成、AI视频生成和人物口型是不同能力，按需要选择，不强制为每个视频都接生视频模型。

## 工具按需求选，不绑定一种方案

配音可用在线预设声线、Piper本地模型、MiniMax API或已有录音；Qwen3-TTS、IndexTTS 2等克隆路线优先复用已有脚本，缺少适配时按对应版本接入。Agent会结合机器、效果和预算推荐可行方案。

基础处理使用Python与FFmpeg，知识动效和合成使用HyperFrames及其Node.js环境；需要生成新图片时接入真实生图工具。安装Skill本身不会附带所有模型或收费账户。

## 最后拿到什么？

**MP4成片、字幕、可重渲染工程、提示词和素材记录、验证报告。** 修改过程有版本可追溯，采用及清理范围由你确认；未经确认，不删除旧产物。

## 隐私与提交边界

根目录 `.gitignore` 对整个仓库生效，默认忽略所有文件，只放行通用说明、技能文档和Python源码。这里的“全局”是本仓库范围，不改动你其他仓库的Git设置。

不得提交API Key、私钥、账号/登录状态、Cookie、个人路径、声音ID、参考录音、文稿、用户配置、接口响应、日志、图片、音视频、字幕、模型、字体、生成工程或压缩包。不要用 `git add -f` 绕过忽略规则，也不要把媒体转成Base64/SVG内嵌进允许提交的源码。示例只使用虚构数据和空占位符。公开仓库不放个人素材，案例展示使用另行授权的公开链接。

提交前在仓库根目录运行：

```bash
python3 scripts/audit_public.py
# 初始化Git并暂存明确的源码文件后，再运行一次审查，然后查看：
git diff --cached --stat
git diff --cached
```

审查脚本检查允许公开的文件内容，以及本地Git索引和可达提交历史；只报告问题位置，不回显敏感值。它是特征扫描，不能代替人工逐项检查。`.gitignore` 不影响已跟踪文件，也不能阻止强制添加；不能因为被忽略就把秘密放进仓库。若密钥曾提交或公开，先在供应商处撤销/轮换，再处理历史，单删当前文件无效。
