# 个人 IP 视频全流程 Skill

把一个选题交给 AI Agent，从角色设计、文案和配音，一路完成镜头编排、知识动效、字幕与成片导出。

## 先看效果

**案例：为什么文件越存越难找？** · 约36秒 · 1920×1080 · 中文配音

案例媒体保存在仓库外，不随源码提交。后续如需公开展示，再填写单独授权的公开链接。

这个案例从独立项目开始制作，包含原创狐狸角色、三视图、场景与人物插画、原创口播、整段配音、真实声学对齐、6个镜头、知识图解动效和15段字幕。视频采用插画人物镜头与纯旁白，没有口型动画或背景音乐。

## 能做什么

- **准备环境与分区**：检查必要工具，创建共享素材库和每条视频的独立项目，生成路径清单。
- **建立个人 IP**：设计原创角色、三视图、笔触细节与场景参考，保持人物镜头的一致性。
- **按效果选工具**：结合当前环境介绍几个可行的生图、生视频与配音方案，说明优劣；选定后安装对应依赖、准备对应脚本，无需前置试听。
- **写稿与配音**：生成原创口播，或从已有文案、角色、音频继续；整段配音后进行声学对齐。
- **编排与剪辑**：按语义设计人物镜头和知识动效，生成字幕，合成并导出视频。
- **减少返工**：核对最新素材决定、人物与道具关系、文字和连线对齐、声画同步；局部修改保留已确定内容。
- **管理版本**：记录候选与修改，收尾先确认采用及保留版本，再按用户确认的具体清单清理旧产物。

## 安装

将本仓库中的 `ip-video-pipeline/` 文件夹放入 Agent 的 skills 目录。Codex 通常使用 `~/.codex/skills/`。刷新技能列表或开启新会话，然后调用 `$ip-video-pipeline`。

[阅读 Skill 全文](ip-video-pipeline/SKILL.md)

## 使用说明

1. 将 `ip-video-pipeline/` 安装到Agent的技能目录；仓库代码与视频工作区分开放置。无需手动逐个运行脚本，Agent按Skill串联步骤。
2. 提供选题、受众、画幅及已有素材目录。没有角色可让Agent创建；复刻声音要提供自己的录音，已有配音则直接导入。
3. Agent检查实际能力，介绍2–3个可行方案及优劣。选定后才安装对应依赖和配置API；不生成前置试听。密钥在本地环境或密钥管理器中配置，不贴进聊天、文稿和配置示例。
4. 在仓库外建立独立工作区，依次完成角色、文案、全文配音、对齐、分镜、镜头与动效、字幕混音、检查和导出。中断后提供同一个项目目录续做，避免重建。
5. 查看成片和报告，确认采用版本；清理旧产物前另核对具体文件清单及删除方式。

新视频：

```text
使用 $ip-video-pipeline，做一条约40秒的中文横屏知识视频。
主题：为什么文件越存越难找？面向经常制作内容的人。
在源码仓库外新建工作区，没有角色就设计原创IP。
先介绍可行的生成方案和优劣，我选定后自动完成制作与检查。
最后交付成片、字幕和可重渲染工程，让我确认版本与清理清单。
```

续做或修改：

```text
使用 $ip-video-pipeline，继续我提供的项目目录。
读取当前状态和已确认素材，保留现有配音，只修改我指出的镜头。
```

如果缺少账号、密钥、模型或参考素材，Agent说明具体缺项，先完成不依赖它的工作；不会默默切换付费服务。自带工具能否生图/生视频取决于当前会话能力，安装Skill不等于安装所有模型。

## 工具准备

需要能读取 Skill 并调用本地工具的 Agent，以及图像生成能力、Python 3.11或3.12、FFmpeg、Node.js 22或更新版和HyperFrames。配音可选择Edge TTS、Piper本地模型、MiniMax API或已有音频；其他服务按选定方案编写专用接入脚本。声学对齐提供stable-ts路线。

Agent会先检查并补齐当前路线缺少的依赖；可用环境与缓存优先复用。API访问权限、模型下载及服务费用取决于实际使用的工具。

[工具接入与安装](ip-video-pipeline/references/tools.md) · [工作区与素材库](ip-video-pipeline/references/workspace.md)

## 配音怎么选

Agent根据你期望的声音和现有环境，推荐2–3个可行选项，讲清优劣再让你选择；选定后直接制作，不增加试听步骤。

- **省事的在线配音**：Edge预设音色，准备少，但依赖联网，也不支持用本适配器克隆声音。
- **本地运行**：Piper适合固定声线；复刻自己的声音可考虑Qwen3-TTS、IndexTTS 2等，需匹配硬件和模型环境。
- **付费API**：例如MiniMax，省去本地模型部署，但需要密钥与预算；音色设计/克隆按服务另行接入。
- **已有工具或录音**：复用当前Agent实际可用的能力，或直接导入已有配音。

复刻音色时需要提供自己的参考音频；付费API服务需要申请对应API Key、开通功能并准备额度。已有配置、脚本和历史成功记录优先复用，不重复跑生成。

生图、生视频也按实际工具选择；不会仅凭大模型名字判断它能否生成素材。

[完整方案比较与对应脚本](ip-video-pipeline/references/providers.md)

## 交付内容

成片MP4、字幕、可重渲染工程、提示词与素材记录、验证报告，以及待确认的版本和清理清单。所有工程仍需使用的素材都会保留，自动制作不会自动授权删除旧文件。

## 隐私与提交边界

根目录 `.gitignore` 对整个仓库生效，默认忽略所有文件，只放行通用说明、技能文档和Python源码。这里的“全局”是本仓库范围，不改动你其他仓库的Git设置。

不得提交API Key、私钥、账号/登录状态、Cookie、个人路径、声音ID、参考录音、文稿、用户配置、接口响应、日志、图片、音视频、字幕、模型、字体、生成工程或压缩包。不要用 `git add -f` 绕过忽略规则，也不要把媒体转成Base64/SVG内嵌进允许提交的源码。示例只使用虚构数据和空占位符。公开仓库不放个人素材，案例展示使用另行授权的公开链接。

提交前在仓库根目录运行：

```bash
python3 scripts/audit_public.py
# 初始化Git并暂存明确的源码文件后，再运行一次审查，然后查看：
git diff --cached --stat
git diff --cached
```

审查脚本检查允许公开的文件内容，以及本地Git索引和可达提交历史；只报告问题位置，不回显敏感值。它是特征扫描，不能代替人工逐项检查。`.gitignore` 不影响已跟踪文件，也不能阻止强制添加；不能因为被忽略就把秘密放进仓库。若密钥曾提交或公开，先在供应商处撤销/轮换，再处理历史，单删当前文件无效。
