# 配音、对齐、拆分

## 配音与完整性

按 [方案选择](providers.md) 使用选定供应商和音色，一次输入整篇定稿，不自行逐句调用拼接；服务超限须说明并选择能容纳全文的路线。Edge适配器保存原MP3并规范化为44100Hz单声道PCM WAV；已有配音用 `tts --provider import --input` 导入，不重配。脚本保留源稿/音频哈希和调用参数。

全文请求成功不等于全文读完。核对开头、专名数字、段落衔接和结尾，必要时用独立转写检查漏句、重复和截断；强制对齐不是全文正确的独立证据，不通过修改ASR文本掩盖错误。原声与文稿不符时先修正输入，再做对齐。

## 强制对齐

`align` 用 stable-ts 对最终 WAV 与定稿进行模型强制对齐，默认 Whisper large-v3；不是普通转写之后硬把字改对。传给模型时只去掉首尾空白，原稿、原音与哈希保持不变，最终短语仍恢复原文全部标点/空白。原始输出保留为 `forced-words.json`，重试另存版本，实际路径写入来源记录。

短语优先在句号、问号、感叹号及适当的逗号处分组，不为了凑字数截断“位置”“图片”等词。5–15字是审阅目标，超出者写进 `review_phrase_ids`，不强行切字。长句根据语义从已有真实词边界重分；字幕可读且时长足够时也可记录理由后保留。这些建议不代替语义审阅。不要在一个模型词内按字符均分时间来硬凑字数。

对齐输出不保证毫秒准确，整数毫秒是存储精度。听取开头、中段、专名、数字与结尾；重叠、零时长、明显漂移需针对受影响段重做模型对齐或实听校准，不裁掉问题来过检查。真实语音与文稿不一致时先修正文稿或配音。

## 显示时间与发音时间

- `acoustic_start_ms/end_ms` 保留声音中的实际区间；可有自然停顿。
- `start_ms/end_ms` 是连续的字幕/剪辑区间；相邻短语在真实停顿中点交接，首段从0开始，末段到WAV真实长度。
- 中点处理只分配停顿的显示归属，不重新估算词的发音位置。
- 长停顿要在分镜中有意处理；没有台词的停顿不意味着应强行删音频。

## 使用其他对齐工具

保存 `audio/alignment-acoustic.json` 为数组，每项：`text`（包含对应原文标点与空白）、`acoustic_start_ms`、`acoustic_end_ms`。所有 text 拼接必须逐字符等于 narration.txt。声学时间必须来自工具或实听校准，不接受按字数估计。

同时保存 `audio/alignment-provenance.json`，包含 `method`、`model`、`script_sha256`、`audio_sha256`。哈希由 Python hashlib 读取真实文件计算，不能写死。然后运行：

```bash
python3 "$SKILL_ROOT/scripts/pipeline.py" timeline /absolute/project
python3 "$SKILL_ROOT/scripts/pipeline.py" validate /absolute/project
```

保留模型原始结果与人工校准说明。`timeline` 检查声学区间无重叠后生成连续显示时间轴，不承担声学推理。只修改分组时合并或重分模型已有边界，更新来源和时间轴，令分镜失效。

## 音频拆分

`split` 按连续显示边界换算采样点，使用 WAV PCM 解码帧切出 P001.wav 等。最后一段严格到原文件末采样点；片段拼接可逐采样还原原WAV的数据。用它进行逐镜制作、试听或交给工具；整片的旁白轨优先直接用原 WAV，避免重复编码与拼缝。

`audio/segments.json` 记录每片段相对路径、起止采样点和文案。字幕时间不是最终视频每一镜的边界：一个镜头可覆盖若干短语；故事板不得把同一段旁白播放两次。

## 混音

沿用本片已确定的原声、语速和配乐方向；只要求音效时不自行加BGM。音乐与音效通过media-use或用户素材取得并记录许可，没有合适配乐可保留纯旁白。

音效落在有意义的画面动作上，不机械每句末或固定间隔响一次。按实际播放检查刺耳提示音、音乐循环接缝、结尾淡出和人声遮盖，响度合格不等于听感合适。

仅改混音尽量保留原视频流，用媒体流哈希或时间对比检查未要求改动的内容。改文案、音色或语速须重新配音及对齐，下游失效规则见 [contracts.md](contracts.md)。
