# 原创文案模块

根据主题、受众和资料生成可直接朗读的中文口播，并单独整理上屏内容和素材需求。

先确定“谁遇到什么具体问题、看完能做成什么”。默认结构可用：可见成果或具体困境 → 一句话解释原因 → 2–4个有因果关系的步骤 → 用例或前后对比 → 回扣成果。不是每篇都需要成果开场，按选题选择。

执行提示：

> 根据给定受众和主题写可直接朗读的原创中文口播。先列核心结论和证据，再写正文。句子短一些，术语首次出现用具体例子解释。一个段落推进一个意思，把“提升效率”改成明确动作和结果。教程每步讲清输入、操作、产出。删掉客套开场、空泛赞美和重复结论。不能把未经实际执行的效果写成“我试过”。如含时效性产品能力、价格和数据，查官方来源并记录日期。将旁白单独保存，不把场景编号、括号内导演指令或链接读出来。

教程先交代观众能得到什么、为什么做这一步，再讲操作；不在收益未明确时堆工具定义。结果开场只展示真实且匹配的已有成果，素材暂缺就标待补。

时长先按自然语速粗估，只用来控制稿长，绝不用于镜头时间。配音完成后的实际时长才是制作依据。超长时删减重复说明并重新合成，不粗暴加速追时长。

`screen-plan.md` 每段记录：口播、观众看到什么、是否需要真实录屏、上屏提示词/操作命令、事实来源。关键实操没有素材时可先补录；演示性图形标“示意”，不能伪造成功记录。
