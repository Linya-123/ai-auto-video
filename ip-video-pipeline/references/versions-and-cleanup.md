# 版本选择与确认后清理

制作中记录修改版本，收尾时让使用者选定最终版本，并确认保留与删除范围，再清理旧产物以减少磁盘占用。适用于角色图、三视图、场景图、视觉编排图、分镜表、文案、配音、字幕、镜头动画、样片、成片及临时渲染文件。

## 制作过程中记录版本

为需要比较或回退的修改保留明确版本，如 S003-v01.png、S003-v02.png；不要用“最终版”“最终最终版”代替版本号。不对每次读取或无变化操作重复备份。不覆盖用户已确认采用或要求保留的版本。

在本任务 `versions.json` 中登记每个逻辑产物的版本号、相对路径、大小、SHA256、修改要点、替代哪个版本、验收状态、是否被工程引用，以及 `agent-selected` / `user-approved`。图片保存可点击预览或联系表；视频/音频提供可播放文件；编排图与文案提供可读对比。生成失败但落盘的文件也要登记，以便收尾盘点。

当前入口指向实际采用版本及可复现脚本，旧脚本只作历史记录；保留工程不能依赖拟删除的旧MP4。已有角色、用户原始输入、共享库与工具环境不属于本片旧版本，不自动纳入删除名单。

## 1. 必须确认最终采用版本

收尾时先展示“产物 → 候选版本 → 修改差别 → 当前工程使用版本 → 建议采用版本”。图片用预览帮助选择，不能只给一串难辨认的文件名；文案或分镜指出关键差异。

明确询问使用者最终采用哪版、还想保留哪些备选。可以一次确认整套采用方案，不要求逐文件反复询问。已明确确认的版本直接写入方案供核对，不重复要求选择；尚未选定的不能按最新文件、最大版本号或AI自检通过来推定。

自动制作模式 `auto` 也必须保留这一最终版本确认；“全自动完成”不等于授权删除旧文件。用户可以确认采用版本但暂不清理，此时交付成片并将清理标记为待确认，不阻塞查看和使用成片。

## 2. 生成可审核的保留/删除清单

先将采用版本接入工程，核对素材引用、字幕、配音和分镜的一致性；如版本选择改变了成片，重新生成并完成相应验证。再读取工程文件、素材账本、角色参考、音频时间轴和渲染依赖，确定保留集合及其依赖。

写入本任务 `reports/cleanup-plan.json` 与 `reports/cleanup-plan.md`：

- 清单ID/修订号、所属任务、编制时间。
- 最终采用版本及对应文件。
- 保留项：文件相对路径、大小、SHA256、保留原因；包括用户要求保留的备选。
- 拟删除项：逐个具体文件的相对路径、大小、SHA256、删除原因、已由哪个版本替代。
- 待确认项：引用关系不明确、用途不明或尚未确定版本的文件。默认保留，不混入删除项。
- 预计删除文件数、合计文件大小及删除方式。文件大小合计是估计值，实际释放空间可能受回收站、硬链接或系统快照影响。
- 确认状态默认 `pending`；不能由脚本扫描或AI检查自动改成用户批准。

展示可读清单，明确问：“采用哪些版本？保留清单是否完整？是否删除清单ID中的这些旧文件？”两类确认可以合并在一次请求中，但必须展示具体可展开的文件清单。不能只问“要不要清理一下”。

删除方式要写清楚：移入系统回收站可恢复但通常不会立即释放磁盘空间；永久删除需使用者明确接受。不得为腾空间顺手清空整个回收站。不能把文件移到archive后宣称已释放空间。

## 3. 只有明确确认后才执行删除

只有使用者针对这份具体清单确认删除后，才通过文件工具或本地命令删除获批文件。批准记录保存到 `reports/cleanup-approval.json`：对应清单ID、清单文件哈希、用户确认内容、保留例外及删除方式。不因超时、沉默、之前同意制作视频或泛泛要求节省空间就执行删除。

用户调整保留项时先从删除清单排除这些文件及其依赖；如果有新增删除对象、版本变化或文件内容变化，展示修订清单，对改变的范围重新确认。已批准且没有变化的部分不重复询问。

删除前再核对每个文件的路径、SHA256和依赖关系，确认任务没有正在写入或渲染相关文件。采用明确的文件列表逐项操作，不使用 `rm -rf *`、递归清空目录或按“旧/错误/temp”字样批量猜删。

只处理当前任务目录内的获批普通文件；路径越界、符号链接、共享资产、其他任务文件和未盘点目录先保留。目录清理只有在目录已空、属于本任务且在获批范围内时进行。工具依赖、模型缓存、共享库和用户原件若确需另行清理，单独列清单获得针对它们的确认。

工程还引用的文件即使版本号较旧也保留；先替换引用并验证成功，才有资格进入新删除清单。不要误删仅保留成片就无法恢复的配音、角色基准、字幕、字体、动效源文件等重渲染依赖。完整渲染还原所需文件与用户明确要求保留的文件优先。

## 4. 清理完成后的检查

记录 `reports/cleanup-result.json`：已删除、已保留、跳过、失败的具体路径及原因，成功处理的大小合计、采用版本和删除方式。失败时保留结果，不把部分完成写成全部清理完成。

检查保留文件存在且哈希一致、项目引用可解析、成片可打开；必要时运行 HyperFrames check。如果共享资产已获单独删除授权，同步更新索引并检查其使用者。更新版本索引和素材账本，对删除项保留轻量文字记录而非继续复制大文件。保留确认清单和执行结果用于追溯。

向使用者报告最终采用哪版、留下哪些关键产物、实际删除了多少文件，以及是否仍有待确认内容。未获删除确认时写“成片已交付，旧版本待确认清理”，不能自动删除。
