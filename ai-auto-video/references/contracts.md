# 项目契约与质量检查

所有工程内媒体路径相对项目根目录；启动工具时解析为绝对路径。密钥只由供应商环境变量/安全存储读取。不要把用户机器路径、授权音色信息放入分享包。

## 分镜 JSON

`storyboard.json`：

```json
{
  "timeline_sha256": "由audio/vo-align.json真实文件计算的SHA256",
  "shots": [
    {
      "id": "S001", "start_ms": 0, "end_ms": 4200,
      "text": "这里必须是此时间范围的定稿原文。",
      "roll": "A", "type": "人物", "perspective": "主角",
      "intent": "看出信息散乱带来的困境",
      "design": "中景，主角坐在桌前，两侧资料堆叠，字幕区域留白",
      "change": "说到找不到时，人物依次翻动两摞资料，未找到目标",
      "result": "目标仍未找到，主角看向待整理的材料",
      "transition": "下一镜保留资料位置，将其展开为分类图",
      "assets": [], "status": "planned"
    }
  ]
}
```

示例数字不是可复用时间；根据实际时间轴生成。`validate --storyboard` 检查镜头顺序、整片覆盖、短语边界、原文、功能类型及必要设计字段。字幕SRT和编排表以 `vo-align.json` 为上游，不另手工维护一份时间。

## 状态与失效传播

局部修改先明确反馈、受影响镜头/时间段和必须保留的参数，完成后检查目标项与无关项。仅改画面保持原旁白和时间轴，不因修一个字体或场景重做全片。

`project.json` 中 `stages` 记录每阶段 `status`（pending/running/verified/failed）、`inputs`哈希、`outputs`路径、`validation`报告路径；Agent在实际检查后更新。单步只更新实际执行项；其余保持原状态。上游修改仍须标记受影响下游待重做，但不自动执行超出本次范围的阶段。视觉草案不满足正式分镜验证条件；只记录草案产出，不将正式分镜阶段标为verified。`decisions` 记录选择、原因及 `agent-selected/user-approved`。

依赖顺序：
- 文案/声音变更 → 配音、对齐、分镜、合成、导出失效。
- 声学对齐变更 → 显示时间轴、分镜、合成、导出失效。
- 角色规范变更 → 受影响人物资产、合成、导出失效，音频仍可复用。
- 一个镜头的图/动效变更 → 该镜与总合成/导出失效，不重做整片音频。

脚本对音频/时间轴/分镜以哈希拦截部分过期复用；其他依赖由 Agent 在状态中管理，不能把这个脚本称作全自动缓存调度器。失败或取消的生成任务保留任务ID、参数、供应商返回状态；先查询再考虑重试。非付费的技术失败最多额外重试1次；付费请求超时或状态不明不自动重提，按providers.md检查任务与计费记录。

## 素材账本

每项记录 `id`、相对 `path`、来源URL或生成工具/模型、参考图路径、提示词路径、用途、许可/授权依据、`accepted`、问题说明。图形示意和真实证据要区分。第三方源码保留其许可及通知；不用“可下载”替代“可再分发”。

## 版本与清理记录

修改时维护versions.json，收尾根据 [版本选择与清理](versions-and-cleanup.md) 生成采用、保留、拟删除清单。先完成版本预览和具体文件清单，再让使用者确认；确认后按列表执行删除，保存approval与result记录。待清理状态不等于获准删除。
