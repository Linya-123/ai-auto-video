# 先选效果，再接工具

首次制作、首次建立音色或用户主动换方案时读本页。先做能力盘点和方案选择，再安装所选依赖。已确认且可用的配置继续复用；不要每条视频重新询问。用户明确委托 Agent 选择时，在其预算和要求内选择并记作 agent-selected，不伪造用户确认。

## 1. 先判断实际可用能力

不要根据“使用哪个大模型”猜测能力。读取当前会话实际工具、已安装 Skill、系统/内存/显卡、可复用环境、模型缓存和用户已配置服务。只检查密钥是否设置，不显示其内容。不用付费生成请求做连通性探测。

在 `reports/capabilities.md` 分别记录：文案、生图、图生图、多参考图、生视频、图生视频、口型、配音、音色设计/克隆、声学对齐、动效渲染。每项写实际工具或脚本、已验证/已配置未验证/不可用、输入输出限制及下一步。安装了一个 Skill 不等于接口可调用；普通聊天模型也不等于自带图片或视频生成。

## 使用前需要用户准备什么

- **复刻自己的声音**：提醒用户上传自己的参考音频，或提供本地文件路径；根据所选模型要求检查格式、时长、清晰度与参考文本。需要准确转写时由 Agent 协助完成，不借用分享包作者的录音或声音ID。已有可用克隆音色则直接复用，不重复上传或复刻。
- **付费API服务**：说明需要注册对应服务、申请API Key，并开通所选功能和准备额度；给出该供应商官方控制台入口。确认账户地区与接口匹配，指导用户在本地环境配置密钥，不要求把密钥发在聊天里。已有配置直接复用。
- **本地模型**：说明需要兼容硬件、运行环境和模型文件，通常无需云端API Key。软件是否开源与是否收费不是同一个判断；开源模型的托管API也可能收费。

## 2. 把声音需求说清楚

先从已有需求提取信息；缺少时用一句话询问期望效果，例如：“你想要清晰自然的现成声音、为角色设计一个新声音，还是使用自己的声音？更在意省事、离线，还是情绪表现？”不要先让普通用户选模型编号。

- **现成音色**：选合适的男女声、语言、年龄感、语速和情绪；不是创造新声音。
- **设计新音色**：通过描述生成角色专属声音；必须选择真的提供 voice design 的工具，普通 TTS 接口不能冒充此能力。
- **使用自己的声音**：可直接录音，或用本人/已获授权的参考录音做克隆。记录参考音频、转写要求与真实授权来源；不把供应商音色ID当作原始声音模型。
- **已有满意配音**：直接导入，省去生成。先核对口播内容，再做时间轴。

结合机器、联网条件、期望效果和预算，仅展示2–3个可行选项。每个选项说明能得到什么、主要不足、是否付费、是否上传声音/文本、安装工作量。未知预算而候选含收费服务时，先确定预算，不能因用户选择“效果好”就无限生成。

## 3. 配音路线比较

| 路线 | 适合什么效果 | 优势 | 代价/限制 | 本包怎样执行 |
|---|---|---|---|---|
| 当前 Agent 已有语音工具 | 工具实际支持的现成音色、设计或克隆 | 复用已有能力，少配环境 | 能力、账户计费、导出格式由工具决定 | 读真实工具说明生成，再用 import 规范化 |
| Edge TTS 在线预设声线 | 快速做清晰的知识口播 | 无需自行配置API密钥，准备较少 | 需要联网；不能用本适配器设计/克隆音色；可用性受在线服务影响 | 内置 edge 适配器 |
| Piper 本地模型 | 离线、固定声音的基础旁白 | 下载模型后可本地运行，有CPU路线 | 自然度、语言和音色取决于所选模型；不等于任意声音克隆 | 内置 piper 适配器，用户选择对应ONNX音色 |
| Qwen3-TTS / IndexTTS 2 本地克隆 | 使用自己的声音，尤其已有兼容Mac环境时 | 旧制作项目已有MLX路线的运行记录与脚本可参考 | 社区运行时需匹配硬件与模型版本；旧记录中IndexTTS更慢，不能推广成所有机器的结论 | 优先复用用户已有脚本并参数化路径；不作为本包已内置跨平台适配器 |
| CosyVoice 本地模型 | 希望用参考声音定制中文等口播 | 提供参考声音等生成路线，可本地部署 | 环境、模型与硬件准备较重；效果随参考录音而变 | 选定版本后按官方示例生成项目专用脚本，再 import |
| MiniMax 等付费 API | 希望少配本地环境、尝试表达力更强的声音 | 使用托管模型，部分服务另提供音色设计/克隆 | 需密钥和费用预算，文本/参考声音发送到服务端 | 内置 MiniMax 国际站全文TTS；设计/克隆及其他服务另接专用脚本 |
| 本人录音/已有音频 | 最直接保留真实声音或已有成品 | 不需再次生成 | 需要录音质量、内容与文稿一致 | 内置 import 适配器 |

不承诺某路线一定“最像真人”，说明模型和音色差异，不强制生成试听候选。开源客户端、开源模型、可离线运行和模型允许的用途是不同事项；按选中的软件与音色模型说明记录许可。收费以选择时的官方价格、模型和账户地区为准，不在 Skill 写死报价。

资料核对：2026-09-13。[Edge TTS](https://github.com/rany2/edge-tts)、[Piper Python API](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md)、[CosyVoice](https://github.com/QwenAudio/CosyVoice)、[MiniMax HTTP TTS](https://platform.minimax.io/docs/api-reference/speech-t2a-http)。执行前复核所选版本；这不是所有供应商的支持承诺。

## 4. 选择后直接制作并复用

不设置试听或样音确认环节。给用户说明2–3个可行方案的效果、优劣、费用与安装要求；用户选定后，准备对应工具和脚本，直接生成正式配音。用户明确授权 Agent 自选时按其要求和预算执行，并如实记录。

更新 `project.json.tts` 中的 provider/model/voice/语速，`generation.image/video` 中的生成配置，以及 `decisions` 中的 user-approved 或 agent-selected 与理由。未指定具体声线时，Agent根据角色定位从所选服务实际可用声线中选取，不再增加选声音的必经确认。模型版本、参考素材ID和预算一并记录；API密钥只放执行环境，分享时剔除私人声音ID、录音和账户资料。

将用户希望跨片复用的非敏感偏好写入工作区配置，下一条项目复制；个人声音引用保留在私有素材库。不重建声音、不默默降级。原服务不可用时保留产物和失败原因，说明替代方案的差别再决定。换音色需重新配音、对齐和相关下游产物。取消的是前置试听，成片的内容与音频质量检查仍执行；旧产物清理仍须用户确认具体清单。

## 5. 按方案安装并运行

以下使用初始化时输出的真实 `PROJECT`、`STUDIO` 和 `SKILL_ROOT`；不要照搬占位路径。先准备FFmpeg。安装器明确选择TTS与对齐依赖，Piper的模型另行按用户选定音色下载并记录版本；CosyVoice使用自己的兼容环境。

```bash
# 按 workspace.md 安装所选路线；已有环境直接复用。
# PY 指向安装器打印的虚拟环境Python路径。
"$PY" "$SKILL_ROOT/scripts/pipeline.py" tts "$PROJECT" --provider edge --voice zh-CN-XiaoyiNeural
"$PY" "$SKILL_ROOT/scripts/pipeline.py" tts "$PROJECT" --provider piper --model /absolute/selected-voice.onnx --speed 1.0
# 环境预先设置 MINIMAX_API_KEY；模型、音色ID必须来自用户实际可用列表。
"$PY" "$SKILL_ROOT/scripts/pipeline.py" tts "$PROJECT" --provider minimax --model SELECTED_MODEL --voice SELECTED_VOICE_ID --speed 1.0
"$PY" "$SKILL_ROOT/scripts/pipeline.py" tts "$PROJECT" --provider import --input /absolute/approved-narration.wav
```

上面四个 tts 命令是互斥示例，不要依次运行。已有正式音频会拒绝覆盖。新项目默认 provider 未选定；明确选择后才运行；成功调用会保存所用参数，用户选择或代理决策由 Agent 另行记入 decisions。旧项目已选 Edge 仍可直接续用。Edge用 `--rate '+10%'`，Piper/MiniMax用 `--speed`，两种参数不可混用。MiniMax内置适配器只支持国际站 `api.minimax.io` 的同步全文接口，不自动改用中国站密钥/域名。

所有路线最终输出 `audio/vo-full.wav`（44100Hz、mono、PCM）和 `tts-receipt.json`，保留原音、源稿/音频哈希与真实参数。导入不是验证：仍须试听核对文稿；音色定稿后接原有 align → timeline → validate → split，不能根据供应商字幕就跳过声学核查。

付费请求前先写 `audio/provider-attempt.json`。超时/错误不自动重提，同目录再次提交会被拒绝；先检查 trace_id、账户请求记录与计费状态。需要重做时经用户已有预算授权选择新版本，保存前次记录。不要通过删除请求记录规避检查。音频已经返回但规范化失败时，直接从保存的原音恢复，不能重新付费生成。

## 6. 生图、生视频也按同一原则选择

- 有可调用的原生生图/图生视频工具：复用实际工具，并检查是否支持角色参考、多图输入、宽高比、输出下载与任务查询。
- 需要API：选用户已有服务或说明成本后选择新服务，再读该服务的当前文档和已安装适配器；没有密钥不假称接通。
- 本地模型：先确认机器与工作流确实支持，按所选模型准备独立环境和权重，不让所有用户下载一套大模型。
- 已有图片/视频：归档并复用；无法自动生成时可明确使用用户提供的素材继续。

“图像+HyperFrames动效”是可选的知识动画路线；“AI生成视频片段”是另一项生成能力；“人物对口型”还需相应工具，三者不可混为一谈。先解释成片差别和成本，再由用户选择；保留已接受案例的原路线。新任务若用户未要求生成视频片段，可推荐插画+知识动效，不能称已调用生视频模型。

## 7. 优先复用已有脚本与运行记录

用户已有制作项目时，先寻找对应方案的脚本、依赖锁定文件、模型版本、成功响应和产物记录；已有证据不因当前会话没运行就判成“从未实测”，也不要求为证明成功重复生成。说明历史实测与当前新增适配器验证的区别。

复用时把输入稿、参考录音、参考文本、模型、输出位置改为明确参数，移除固定个人路径、录音文本、声音ID和密钥配置。保留真实依赖版本及必要补丁说明。旧脚本中“已有同名分段就跳过”不能作为新稿续做依据，须核对源稿/模型/参考声音哈希。旧项目逐段生成属于历史流程，不直接冒充本Skill的全文配音；适配所选引擎的全文能力，超限时明确说明。只做必要的静态检查，不重复跑生成。

## 8. 其他供应商的针对性脚本

未内置且没有可复用脚本的方案选定后，Agent完成接入，不能只把写脚本的任务甩给用户：

1. 读取所选供应商/模型当前官方文档与实际安装版本，确认地区、认证、全文限制、输出格式、价格及可用声线；记录文档地址和日期。
2. 在项目 `tools/providers/` 创建独立脚本及最小依赖文件、运行说明。按该接口真实请求/响应字段实现，不凭空套用“OpenAI兼容”协议。密钥只读环境变量。
3. 声音设计/克隆先走其专门接口或本地推理流程，保存真实返回的声音引用及允许复用的范围，再接全文TTS。需要参考录音时明确格式、长度、文本要求；缺用户素材则停在该输入，不伪造。
4. 网络设置超时；付费不自动重试。异步生图/生视频记录任务ID并查状态，恢复时先查旧任务。校验返回的媒体类型、完整性和实际输出，保存参数与版本，不把HTTP200等同生成成功。
5. 先做本地参数与响应解析检查，不强制生成试听样音；正式调用后检查真实输出。音频走 import 统一接口；图片/视频登记真实文件、尺寸/时长、提示词及参考素材ID，继续既有镜头编排。
6. 明确验证等级：仅查文档、模拟接口测试、正式生成成功。缺访问权/硬件时报告具体缺口，不声称任意服务已支持。

内置 Edge 已有真实中文样片验证；import 可本地验证格式转换。Piper、MiniMax 的适配代码按官方协议编写，测试可模拟模型/API；未用用户所选模型或账户实际生成前，不能宣称声音效果已验证。CosyVoice和其他供应商目前属于按选择生成专用脚本的路线，不是已内置运行完成的适配器。
